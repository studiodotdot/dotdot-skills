# Vanilla Deck 스킬

## 개요

**발표자료는 교육자료와 전제가 다르다.**

| | vanilla-slide (교육) | vanilla-deck (발표) |
|---|---|---|
| 전제 | 학습자가 혼자 다시 본다 | 발표자가 말로 채우고, 나중엔 PDF로 읽힌다 |
| 슬라이드 역할 | 개념의 저장·인출 | 주장의 근거 제시 |
| 한 장의 구조 | 예고 → 전개 → 정리 → 활동 | **완결 문장 제목** → 시각 앵커 하나 → 결론 밴드 → 출처 |
| 색·배경 | 챕터별 파스텔 배경 | 흰 바탕 + 다크 표지·간지, POINT 1색 자유 사용 |
| 단축키 | F·I·N·S | **F·I 2키** — 노트·발표자 모드 없음 |

시각 문법의 근거는 국내 PPT 디자인 전문 업체 발표자료 포트폴리오 실측(15건 149장)이다. 원본 이미지 라이브러리가 있으면(작성자 로컬: `~/Downloads/레퍼런스_슬라이드_260919/발표/`) **덱을 만들기 전에 같은 유형의 레퍼런스 장을 2~3장 직접 보고 시작한다.** 라이브러리가 없는 환경이면 이 문서의 부품 설명과 템플릿 샘플을 기준으로 한다.
(cover/divider/toc → `01_*/01~03`, 3단 → `01_*/04`, 카드 격자 → `04_*/02`, 60/40 → `19_*/03`, 목표·기대효과 → `19_*/07`,
타임라인 → `01_*/10`, 사진 카드 → `02_*/03`)

## 파일 생성 절차

1. **용도 파악** — 사내 보고 / 외부 제안 / 공모전 중 무엇인지. 흐름·문체는 `references/flows.md`
2. **콘텐츠 설계** — 장마다 "이 장의 결론 한 문장"을 먼저 적는다. 결론이 안 나오는 장은 합치거나 뺀다
3. **`assets/template.html` 복사** → 새 파일
4. **슬라이드 영역만 교체** — `✏️ 슬라이드 영역` 안의 `<section>`들만. `🔧 덱 헬퍼`와 `⛔ 엔진` 아래는 건드리지 않는다
   - `<title>`, `<body data-logo="조직명 또는 브랜드">` 교체
   - 각 section에 `id="slide-N"` + `data-title`, 간지에 `data-chapter`
   - 화자 노트(`<aside class="notes">`)는 쓰지 않는다
   - 템플릿 예시 수치는 **전부 교체**. 덱 전용 CSS는 `<style>` 안 `✏️ 덱 전용 스타일` 자리에
5. **팔레트** — 사용자가 색을 주면 아래 컬러 규칙으로 `:root`를 채운다. 안 주면 기본(블루) 유지
6. **검증** 후 저장 — 파일명 `{주제}_{보고|제안|공모전}_{YYMMDD}.html`
7. **최종 보고** — 내가 추론해서 넣은 문장 목록 · `확인 필요`로 비워 둔 자리 · 색을 바꿨다면 그 사실

## 장 유형

| 클래스 | 용도 | 구성 |
|---|---|---|
| `slide--cover` | 표지 | 다크 배경 + `.glow` 그라데이션 덩어리 + 연도(회색 큰 숫자) + **흰 큰 제목 2줄** + 날짜 + 우하단 로고 |
| `slide--toc` | 목차 | 좌측 34% 기하 장식 블록(`.toc__deco`) + "Contents / 목 차" + POINT 번호 목록(소항목은 `<small>`) |
| `slide--divider` | 간지 | 다크 + 우상단 큰 챕터 번호 + 흰 가로선 + 큰 제목 + 부제(챕터 결론 한 문장). `data-chapter` 필수 |
| `slide--page` | 본문 | `.head`(3종 택1) → `.body` → `.foot`. 헤더 내비·페이지 번호·로고는 헬퍼가 채운다 |
| `slide--closing` | 마무리 | 표지와 같은 다크 + 결론 한 문장 |

### 본문 제목 영역 3종

| 클래스 | 생김새 | 언제 |
|---|---|---|
| `.head` (기본) | 연회색 그라데이션 밴드 · 좌상단 `01 \| 챕터명` · 우상단 챕터 내비 · **큰 완결 문장 제목(2줄까지)** | IR·전략·성과 보고 — 제목이 곧 주장 |
| `.head--num` | 흰 배경 · 좌측 POINT 번호 박스 + 짧은 주제 제목 · 우측 내비 · 아래 가는 선 | 공공·기관 보고, 현황 정리 장 |
| `.head--dark` | 다크 밴드 + 흰 제목 | 매뉴얼·부록·근거 자료 장 |

```html
  </div>

```

## 발표자료 규칙 (적용 우선순위 순)

**모든 규칙 위에 — 지어내지 않는다.** 입력에 없는 수치·세부 시간·실적·출처는 만들지 않는다. 가격·핵심 수치가 빠졌으면
만들기 전에 묻는다. 아래 규칙과 부딪히면 이게 이긴다.

1. **제목은 완결 문장** — "3분기 현황" ✗ → "실습 비중을 올린 3분기에 만족도가 최고치를 기록했다" ○. 2줄까지 허용, 크게(화면 폭의 1/2 이상)
2. **한 장에 시각 앵커 하나** — 차트·카드 격자·목표 알약·타임라인·사진 카드·지도 중 하나가 장을 지배한다. 표만 있는 장은 60/40으로 큰 세로 제목이나 도식을 붙인다
3. **결론은 하단 밴드로** — `.conclusion`(큰 글자 중앙, `<q>` 안 핵심어 POINT) 또는 `.lead-band`(다크 띠). 제목이 이미 결론이면 생략 가능
4. **신뢰 장치** — `.foot__src`에 `Source:` 또는 `기준:`, 차트에 `.unit`, 각주는 본문 `1)` + 출처 줄 정의. 출처를 모르면 `Source: 확인 필요`로 두고 보고. 우리가 제시하는 숫자(가격·계획)는 `기준: 본 제안 (날짜)`
5. **표는 세로선 없이** — `.tbl`: 헤더만 POINT 틴트, 본문 가로선만, 숫자 우측, 강조 행 `tr.hi`. 항목·값 정리는 `.kv`
6. **차트는 장식 제거 + 강조 하나** — 격자·눈금 없음, 값은 막대 위, 강조 막대만 POINT + `.bar.hi`(타원 강조). 다크 헤더 스트립 안에 차트 제목
7. **현재 위치 표시** — `.head__nav`를 비워 두면 헬퍼가 챕터 내비를 채운다(현재만 POINT). 간지 없이 본문에 `data-chapter`를 달아도 잡힌다
8. **빈 곳은 받은 정보로 채운다** — 아래가 비면 `.kpis`·`.steps`·`.dots`·`.conclusion`으로 채운다. 못 채우면 장을 합친다. `.grow`를 앵커에 붙이면 남은 높이를 채운다
9. **사진은 풀블리드·원형·세로 카드만** — `.pcard`(사진 위 텍스트 + 노란 순위), `.visual`(원형 슬롯). 어중간한 사각 사진 금지. 이미지는 `style="--img:url(…)"`

## 컬러 규칙

레퍼런스 업체는 고객사 CI를 받아 쓴다. 따라서 색은 **역할**만 정해져 있고 값은 덱마다 바뀐다.

| 토큰 | 역할 | 실측 |
|---|---|---|
| `--ink` `--ink2` `--muted` | 글자 3단 (검정 → 회색) | 제목은 거의 검정, 본문 진회색, 캡션 회색 |
| `--point` | **자유롭게 쓴다** — 숫자·선·배지·체크·차트 강조 막대·핵심어·번호 박스·내비 현재 항목 | 빨강·파랑·시안 등 CI 1색. 면적 제한 없음, 다만 큰 면은 `--point-tint`로 |
| `--point-tint` | 영향 박스·표 헤더·KPI 바탕 | POINT의 8~12% 틴트 |
| `--c1` `--c2` `--c3` | 카드 헤더·목표 알약 **3색 세트** | 빨강/오렌지/보라, 초록/하늘/파랑 같이 CI + 인접 2색. 단색으로 가려면 셋 다 `--point` |
| `--dark` `--dark-soft` | 표지·간지 바탕 / 차트 헤더·타임라인 라벨 | 거의 검정 / 진회색 |
| `--glow1` `--glow2` | 표지 그라데이션 덩어리 2개 | POINT 계열 + 보색 계열 |
| `--yellow` | 사진 위 순위·강조 숫자 | 사진 위에서 튀는 색 |

- **사용자가 색을 주면 그게 `--point`·`--c1`이다.** 밝아서 글자로 못 쓰면 글자는 `--ink`로 두고 면·선·숫자에만 쓴다 — 바꿔 쓴 사실을 보고한다
- `--c2` `--c3`는 사용자가 주지 않으면 POINT의 색상환 이웃(±30~60°)에서 채도·명도를 맞춰 고른다. 눈 아픈 형광 금지
- 흰 배경 위 글자로 쓰는 색은 명암비 4.5:1 이상을 계산으로 확인한다

```python
def lum(h):
    c = [int(h.lstrip('#')[i:i+2], 16) / 255 for i in (0, 2, 4)]
    c = [v/12.92 if v <= 0.03928 else ((v+0.055)/1.055)**2.4 for v in c]
    return 0.2126*c[0] + 0.7152*c[1] + 0.0722*c[2]
def contrast(a, b):
    A, B = sorted([lum(a), lum(b)], reverse=True)
    return (A + 0.05) / (B + 0.05)
```

|---|---|---|---|---|

| 정책 블루 | `#0B7BE5` | `#0B7BE5` / `#2ECBF0` / `#7A4FBF` | 파랑 + 하늘 | 지자체·정책 발표 |
| 공공 스카이 | `#1AA0E0` | `#3BB8A0` / `#1AA0E0` / `#3B6FD9` | 하늘 + 청록 | 공공기관 보고 |
| 연구 웜 | `#E23A5A` | `#E23A5A` / `#F0653A` / `#8A5AC8` | 빨강 + 보라 | 연구용역·과제 보고 |

## 크기

`.slide { font-size: min(1.5vw, 2.6667vh) }` — 1280×720에서 19.2px, 화면이 커지면 비율 그대로 커진다. 부품은 전부 em.
실측 비율: 제목 ≈ 본문 × 2.5, 캡션 ≈ 본문 × 0.7, 좌우 여백 ≈ 폭의 4.4%.

## 글쓰기

- 문체는 용도별 — `references/flows.md`
- 상급자·외부용 덱에 가정·검증 메모·작업 노트를 넣지 않는다. 결과만
- 작성자 표기는 이름만 (직함 없이)
- `<br>`은 문장 끝에서만. 제목 2줄 나눔은 의미 단위로

```bash
C="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
"$C" --headless=new --hide-scrollbars --window-size=1280,720 --virtual-time-budget=3000 --screenshot=s4.png "file://$PWD/덱.html#slide-4"

```

- 전 장 캡처를 **직접 보고** 레퍼런스 장과 나란히 비교한다 — 글자가 작지 않은지, 앵커가 장을 지배하는지, 아래가 비지 않는지
- 본문이 `.foot`을 침범하지 않는지 (침범하면 내용을 줄이거나 장을 나눈다)
- PDF 페이지 수 = 슬라이드 수
