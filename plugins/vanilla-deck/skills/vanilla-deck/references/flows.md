# 용도별 흐름

덱을 만들기 전에 용도를 하나로 정하고 해당 흐름을 따른다. 장 수는 예시다 — 결론 문장이 안 나오는 장은 뺀다.

---

## 1. 사내 보고 (팀장·임원 보고, 성과·현황 보고)

**원칙: 결론 먼저, 결과만.** 보고받는 사람이 첫 장만 보고 덮어도 결론을 알아야 한다.

| 순서 | 장 | 유형 | 담을 것 |
|---|---|---|---|
| 1 | 표지 | cover | 다크 표지. 제목 2줄 + 날짜. 결론은 첫 본문 장 제목이 맡는다 |
| 2 | 핵심 요약 | page | `.head` 완결 문장 제목(전체 결론) + `.kpis` + 목표 대비 `.tbl` + `.conclusion` |
| 3~ | 근거 (챕터별) | divider + page | 챕터마다 `.tri`(차트 → 요인 → 영향) 또는 `.cards3`, 실적 `.tbl` |
| 끝-1 | 이슈와 개선안 | page | `.cards3`(현황·원인·검증) + `.conclusion`, 또는 `.goals`(목표 알약 + 기대효과) |
| 끝 | 요청 사항 | page | 타임라인(`.tl-row`) + 결정 요청 `.dots` + 기한 |

- **문체: 보고서 문체** — 리딩메시지·표·불릿은 개조식 종결(~함, ~임, ~했다/~다)
- 제목은 친근하게 짓지 않는다 — "우리 팀 이야기" ✗, "3분기 교육 운영 결과 보고" ○
- **넣지 않는 것:** 가정·검증 메모·작업 과정·"확인 필요" 같은 내부 노트. 산출물엔 결과만 — 과정은 덱 밖(폴더 문서)에 둔다
- 요청 사항 장이 없으면 보고가 "알림"으로 끝난다. 결정 받을 것이 있으면 반드시 마지막 장에 기한과 함께
- `.tri` 열 제목: 차트 제목 | "~에 기여한 세 가지 변화" | "~에 미치는 영향"
- 핵심 요약 장은 첫 간지 앞이므로 `data-chapter="요약"`을 단다

---

## 2. 외부 제안 (교육 제안서, 영업 제안)

**원칙: 상대 문제 → 우리 해법 → 증거 → 조건.** 읽는 사람은 "왜 이 사람에게 맡겨야 하나"를 찾는다.

| 순서 | 장 | 유형 | 담을 것 |
|---|---|---|---|
| 1 | 표지 | cover | 제안명 2줄 + 날짜. 다크 표지 |
| 2 | 제안 이유 | page | `.head` 완결 문장(상대에게 생기는 변화) + `.cards3`(귀사 현황 3장) 또는 `.tri`(현황 → 설계 방향 → 맞춤 조정) |
| 3~ | 설계 본문 | divider + page | `.split`(세로 큰 제목 + 도식 / `.kv` 개요 + 모듈 `.tbl`), `.steps` 진행 순서 |
| 끝-2 | 결과물 예시 | page | 사진·캡처는 `.pcards`(세로 사진 카드) 또는 `.visual`(원형). 글로 된 산출물은 `.cards3`에 견본 문장 |
| 끝-1 | 진행·비용 | page | `.tl-row` 일정 + 비용 `.tbl` (단위·부가세 명시) |
| 끝 | 제안자 | closing | 이름·연락처·주요 실적. **직함 붙이지 않음** |

- **문체: 정중한 경어체** — "~합니다", "~드립니다". 리딩메시지도 경어체로 통일
- 가격은 덱 만들기 전에 사용자에게 확정받는다 — 추측으로 넣지 않는다
- 제안 이유 장은 첫 간지 앞이므로 `data-chapter="제안 배경"`을 단다
- `.tri` 열 제목: 귀사 현황 | 설계 방향 | 맞춤 조정
- 가격·시간·인원은 우리가 제시하는 숫자 — 출처 대신 `기준: 본 제안 (날짜)`
- 모듈별 세부 시간을 받지 못했으면 받은 단위(예: 오전·오후)까지만 쓰고 "세부 배분은 협의"로 둔다
- 제안자 장의 실적은 **받은 것만**. 없으면 묻는다 — 물을 수 없으면 이름·연락처·한 줄 소개만 두고 최종 보고에 "실적 비움"을 올린다
- 실적 수치는 출처(`.src`)를 단다 — 외부 문서라 신뢰 장치가 더 중요하다
- 상대 회사 로고·브랜드를 흉내 내지 않는다

---

## 3. 공모전·경진대회 (심사위원 앞 발표)

**원칙: 문제 → 해결 → 성과 수치 → 확산.** 심사위원은 여러 팀을 연달아 본다 — 장마다 숫자 하나가 남아야 한다.

| 순서 | 장 | 유형 | 담을 것 |
|---|---|---|---|
| 1 | 표지 | cover | 성과 한 문장을 제목으로 ("수작업 3시간을 10분으로") |
| 2 | 문제 | page | `.head` 완결 문장 + `.kpis`(기존 방식의 비용·시간·오류 수치) + `.dots` |
| 3 | 해결 | page | `.steps`(만든 것의 흐름) 또는 `.split`(도식 + `.kv`) |
| 4 | 성과 | page | `.tri`(전후 차트 `.bar.hi` → 바꾼 것 → 효과) |
| 5 | 확산 | page | `.goals`(확산 목표 알약 + 기대효과) 또는 `.cards3` |
| 6 | 마무리 | closing | 성과 한 문장 반복 |

- 간지를 쓰지 않는 짧은 흐름이다 — 본문 장마다 `data-chapter`(문제·해결·성과·확산 또는 심사 기준명)를 달아 헤더 내비를 채운다
- `.tri` 열 제목: 이전 | 바꾼 것 | 효과

- **문체: 선언형** — 리딩메시지는 짧고 단정하게 ("3억 솔루션 없이 같은 결과를 냈다")
- 심사 기준(혁신성·효과성·확산성 등)이 공지돼 있으면 장 제목을 그 기준에 맞춘다
- 수상 결과는 공개될 수 있다 — 대외 공개 공모전이면 회사 내부 수치·실명·고객명을 넣어도 되는지 먼저 확인한다
- 발표 시간이 정해져 있으면 장당 1분 기준으로 장 수를 역산한다
